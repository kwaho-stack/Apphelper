# Apphelper

매 시간 지정한 분 범위 안의 랜덤 시점에 클릭 매크로를 실행하고, 핵심 동작의 성공 여부를
GitHub Pages 에서 확인하는 Windows 트레이 앱입니다. 이 프로그램에서는 "클릭"을 **crash** 라고 부릅니다.

- 대상: Windows 10/11, 단일 모니터 (듀얼 모니터·화면 배율 대응 없음)
- 구성: Python + PySide6, PyInstaller 단일 exe

## 용어

| 용어 | 정의 |
|---|---|
| crash | 지정 좌표를 1회 클릭. 끝나면 커서를 원래 위치로 되돌림 |
| 기본동작 | crash(x, y) 와 대기(ms) 단계로만 이루어진 재사용 블록 |
| 핵심 crash | 클릭 전후로 좌표 주변 N×N(기본 5×5) 평균 색상을 비교해 `변함!` / `안변함!` 을 기록 |
| 시간대 슬롯 | 0~23시. 슬롯마다 사용 여부, 실행 분 범위, 블록 순서를 가짐 |

## 사용법

1. `Apphelper.exe` 를 원하는 폴더에 두고 실행합니다. 처음 실행하면 편집 화면이 열립니다.
   이후에는 트레이 아이콘(더블클릭 또는 메뉴 → 편집 화면 열기)으로 엽니다.
2. 왼쪽 라이브러리에서 **기본동작**과 **핵심 crash** 를 만듭니다. "좌표 따기"를 누르면
   화면이 어두워지고, 클릭한 위치가 좌표로 들어갑니다 (Esc: 취소).
3. 라이브러리 항목을 오른쪽 시간대 줄로 끌어다 놓습니다.
   - 줄 안에서 끌어서 순서 변경, 우클릭으로 복제/복사/삭제 (Delete 키도 삭제)
   - 줄 오른쪽 `⋯` 또는 우클릭: 시간대 복사, 붙여넣기(덮어쓰기/뒤에 추가), 모두 지우기
   - 다른 시간대 줄로 블록을 끌면 복사됩니다.
4. 사용할 시간대에 체크하고 실행 분 범위(예: 10~40분)를 정합니다.
   변경 내용은 자동 저장됩니다.
5. 트레이 메뉴의 **실행/일시정지** 로 켜고 끕니다.

### 시범 작동 · 스크린샷 · 상세 디버그

- 시간대 오른쪽 `⋯` → **지금 시범 작동**: 그 시간대 블록을 지금 실제로 한 번 실행합니다.
  실행 중 **Esc** 를 누르면 그 시범 작동만 바로 멈춥니다 (예약 실행은 Esc 로 멈추지 않음)
  (핵심 crash 좌표도 그 시간대 기준). 편집 창은 잠시 화면 밖으로 비켜 있고, 끝나면 결과를 보여 줍니다.
  결과 페이지에는 올리지 않습니다.
- 핵심 crash 결과가 **안변함!** 이면 그 순간의 화면을 `data\screenshots\날짜\` 에 PNG 로 저장합니다
  (클릭 위치는 빨간 원으로 표시). 예: `21-10-33_21시_01_안변함.png`
- `⋯` → **상세 디버그** 를 켠 시간대는 매 동작(crash 직후, 핵심 crash 클릭 직전·판정 직후)마다
  스크린샷을 저장합니다. 켜진 시간대에는 보라색 `디버그` 표시가 붙습니다. 시범 작동에도 적용됩니다.
- 설정 → **스크린샷 폴더 열기**. 전체 데이터 삭제를 하면 스크린샷도 함께 지워집니다.
- 트레이 아이콘에 마우스를 올려도 실행 시각이나 결과는 보이지 않습니다 (편집 화면에서만 확인).

### 편집 화면 잠금 (비밀번호)

- 트레이에서 편집 화면을 열 때(메뉴, 더블클릭, exe 를 한 번 더 실행) 비밀번호를 묻습니다.
  이미 열려 있는 편집 화면을 앞으로 가져올 때는 묻지 않습니다. 세 번 틀리면 열리지 않습니다.
- 처음 열 때 한 번 비밀번호(4자 이상)를 정합니다. 설정 → **비밀번호 변경** 으로 바꿀 수 있습니다.
- 비밀번호는 해시(PBKDF2)로만 `data/lock.json` 에 저장됩니다. 잊어버리면 앱을 종료하고 이 파일만
  지우면 됩니다 (다른 설정과 동작은 그대로). 전체 데이터 삭제를 하면 비밀번호도 지워집니다.
- 실행/일시정지와 종료는 트레이 메뉴에서 비밀번호 없이 됩니다.

### 마우스 휠

숫자 칸과 선택 상자는 마우스 휠로 값이 바뀌지 않습니다. 휠은 화면 스크롤에만 쓰입니다.
값은 직접 입력하거나 칸의 화살표를 누르세요.

### 프로필

편집 화면 맨 위 **프로필** 에서 여러 세트를 저장하고 바꿔 쓸 수 있습니다.
프로필마다 기본동작, 핵심 crash, 24시간 스케줄을 따로 가지며, GitHub·로그 설정은 함께 씁니다.

- 새 프로필(빈 상태) / 복제(현재 내용 복사) / 이름 변경 / 삭제
- 실행되는 것은 **현재 선택된 프로필** 하나입니다. 트레이 메뉴 → 프로필 에서도 바꿀 수 있습니다.
- 이전 버전의 설정은 '기본' 프로필로 자동으로 옮겨집니다.

### 핵심 crash 이미지 모드

핵심 crash 편집 창의 **찾는 방법**을 "이미지를 찾아 그 중심을 crash" 로 바꾸면, 좌표 대신 이미지를 씁니다.

- **화면에서 캡처**: 화면이 멈춘 상태에서 찾을 부분을 드래그합니다. **파일에서 불러오기**: PNG/JPG/BMP.
- 실행할 때마다 화면 전체에서 가장 비슷한 곳을 찾아(회색조 정규화 상관) 그 중심에 핵심 crash 를 합니다.
  클릭 전후 색 비교(변함!/안변함!)는 좌표 모드와 같습니다.
- **일치도 기준**(기본 90%)보다 낮으면 클릭하지 않고 `실패` 로 기록합니다 (실패 이유에 최고 일치도 표시).
- 시간당 변동(dx, dy)은 이미지 모드에서 쓰지 않습니다.
- 이미지는 4×4 ~ 400×400 px. 단색 이미지는 위치를 찾을 수 없어 받지 않습니다. 버튼 글자처럼
  모양이 뚜렷한 부분을 작게 자르면 빠르고 정확합니다.
- 찾을 이미지는 `data/config.json` 안에 압축해서 저장되며, 실행 중 읽은 화면은 메모리에서만 씁니다.

### 핵심 crash 확인하기

- 핵심 crash 편집 창의 **지금 테스트** 버튼: 현재 시간대 좌표로 실제 crash 를 한 번 하고,
  클릭 전/후 평균 색과 결과(변함!/안변함!)를 보여줍니다. 결과 페이지에는 올리지 않습니다.
- 마지막 실행 결과(실패 이유 포함)는 편집 화면 아래쪽에 표시됩니다.
- 새 핵심 crash 의 기준 시간대는 만든 시각의 시간으로 정해집니다.

### 핵심 crash 좌표의 시간별 변동

`좌표 = 기준좌표 + (배치 시간 − 기준 시간) × (dx, dy)`

예: 기준 1시, 좌표 (100,100), dy=+30 → 2시 (100,130), 3시 (100,160), 0시 (100,70).
편집 화면과 핵심 crash 편집 창에 시간대별 좌표가 미리보기로 표시되고, 화면 밖이면 빨간색 ⚠ 로
경고합니다. 화면 밖 좌표는 실행하지 않고 그 시간을 `실패` 로 기록합니다.

### 스케줄 규칙

- 매 시간이 시작될 때 그 시간 슬롯의 분 범위 `[시작분:00, 끝분:59]` 에서 실행 시각(분, 초)을 새로 뽑습니다.
- 앱을 시간 중간에 켜거나 현재 시간 슬롯을 수정하면, 남은 범위 안에서 다시 뽑습니다.
- 일시정지 중에 실행 시각이 지나가면 그 시간은 건너뜁니다.
- 블록 실행 중 하나라도 실패하면(화면 밖 좌표, 삭제된 블록 등) 그 시간은 `실패` 입니다.

## 메신저 상태 감시 (기존 mess 통합)

편집 화면 → **메신저 상태** 탭.

- **주 대상**: 상태 아이콘 정중앙을 **좌표 따기**. "지금 읽은 상태"로 바로 확인할 수 있습니다.
- **기준점**: 이름 목록 아래 흰 빈 공간을 좌표 따기 → 그 자리 색이 기준색으로 등록됩니다.
  기준색과 허용오차(±45) 이상 다르면 로그인 화면·창 가림으로 보고 `확인불가` 로 기록합니다.
- **현황만 볼 사람**: 인원 제한 없이 추가.
- 5초마다 확인하고, 같은 상태가 3번 연속 읽혀야 바뀐 것으로 기록합니다(깜빡임 방지). 기록 시각은
  처음 보인 시각입니다. 하루는 새벽 3시에 마감합니다. 모두 세부 설정에서 바꿀 수 있습니다.
- **가려져도 읽기**: 켜면 화면 대신 **메신저 창을 직접 캡처**해서 읽으므로, 다른 창이 메신저를 덮어도
  감지됩니다(최소화·트레이로 숨김은 안 됨 → `확인불가`). 켤 때 주 대상 좌표에 있는 창을 메신저 창으로
  기억하므로 그때는 메신저가 보여야 합니다. 메신저 창을 옮겨도 좌표를 다시 딸 필요가 없습니다(창 안 위치로 읽음).
  **메신저 창 캡처 시험** 버튼으로 덮인 상태에서 제대로 찍히는지 먼저 확인하세요(검게 찍히면 이 PC 에서는 사용 불가).
- 감시를 꺼도 결과 페이지에는 꺼지기 전 마지막 상태와 기록이 그대로 보이고, **⏸ 감시 꺼짐** 표시가 붙습니다.
- 기록: `data\messenger\logs\날짜.txt` (추가 인원은 `others\이름\`), mess 와 같은 형식.
- **기존 mess 폴더에서 가져오기…**: messenger_status.exe 폴더의 `config.json`(좌표)과 `logs` 를 가져옵니다.
  가져온 뒤에는 기존 messenger_status.exe 를 끄세요.
- 결과 페이지 **메신저 상태**: 현재 상태와 경과 시간, 다른 사람 현황, 오늘·어제 변경 로그.
  (모든 내용은 토큰으로 암호화되어, 같은 토큰을 넣은 브라우저에서만 보입니다)

## PC 종료/다시시작 예약 (기존 closet 통합)

편집 화면 → **PC 전원** 탭.

- 예약 종류(종료/다시시작) + 시:분 예약, +30분/+1시간/+2시간/+3시간, 예약 취소, 지금 다시시작, 지금 종료.
- 예약 1분 전에 항상 위에 알림 창이 떠서 비밀번호 없이 바로 **예약 취소**할 수 있습니다.
- 강제 종료/다시시작 옵션, 윈도우 시작 시 자동 실행 옵션(켤 때만 레지스트리 Run 에 값 하나를 쓰고,
  끄거나 전체 데이터 삭제 시 지움).
- 트레이 메뉴 **종료/다시시작 예약 취소**. Apphelper 를 종료하면 예약도 취소됩니다(확인 창).
- 결과 페이지 **PC 전원**: 설정에서 **결과 페이지에서 PC 종료/다시시작 허용**을 켜면, 같은 토큰을 넣은
  브라우저에서 켜짐 여부·예약을 보고 예약/취소/지금 종료/지금 다시시작을 할 수 있습니다.
  - closet 의 비밀 Gist 대신 이 레포를 씁니다: 명령은 `apphelper-remote` 브랜치 `request.json`,
    PC 상태는 60초마다 `apphelper-status` 브랜치 `status.json` (둘 다 부모 없는 커밋 덮어쓰기, 이력 없음,
    빌드 대상 아님). PC 는 5초마다 명령을 확인하고, 2분 넘게 지난 명령과 이미 처리한 명령은 실행하지
    않습니다(처리한 명령 id 는 `data\remote_state.json` 에 남겨 다시시작 뒤에도 반복하지 않음).
  - 응답이 2분 30초 넘게 없으면 페이지에 "꺼져 있음"으로 나오고 버튼이 잠깁니다.

## 화면 가리기

편집 화면 아래 **화면 가리기** 버튼 → 편집 창은 트레이로 숨고, 1~3초 뒤 화면 전체가 검게 가려집니다.

- 매크로, 메신저 감시, 결과 갱신, 원격 전원·스크린샷은 모두 그대로 돌아갑니다.
  - 검은 창은 **캡처에서 제외**(Windows 10 2004 이상)되어, 색 비교·이미지 찾기·메신저 읽기·스크린샷은
    가려진 검은 화면이 아니라 **원래 화면**을 봅니다.
  - 검은 창은 클릭이 통과하고, 사람이 실제로 누른 키보드·마우스 입력만 막습니다. 매크로가 보낸 클릭은 통과합니다.
  - 가리는 동안 절전·화면 꺼짐을 막고, 마우스 커서도 보이지 않게 숨깁니다(풀리면 원래 커서로 돌아옴).
  - 매크로가 선택 상자·메뉴를 눌러 팝업이 떠도, 창이 나타나는 순간 검은 화면을 다시 맨 위로 올려
    팝업이 비치지 않게 합니다(놓친 경우를 대비해 50ms 마다도 올림). 아주 드물게 한 번 깜빡일 수는 있습니다.
- **검은 화면 비밀번호**: 편집 화면 비밀번호와 **따로** 정합니다 (설정 → **검은 화면 비밀번호**, 처음 가릴 때도
  물어봄). 한/영 상태와 상관없이 영문 자판 기준으로 읽으므로 영문·숫자·기호만 됩니다. 검증값만
  `data\cover.json` 에 저장되고, 잊으면 이 파일을 지우고 다시 정하면 됩니다.
- **해제**: 검은 화면에서 키를 누르거나 **클릭**(마우스 이동·휠은 해당 없음)하면 그때부터 **5초** 안에
  검은 화면 비밀번호를 치면(Enter 없이) 풀립니다. 틀린 글자가 섞여도 5초 안에 마지막에 정확히 치면 되고,
  Backspace 로 한 글자 지울 수 있습니다. 풀리면 앱은 트레이에 그대로 있습니다.
  가리는 동안 친 키는 다른 프로그램에 전달되지 않습니다.
- **입력 비상종료**: 5초 안에 비밀번호를 못 치면 차례로
  1. PC 를 잠그고(Win+L 과 같음) 잠금 화면이 뜬 것을 확인한 뒤
  2. 화면에 떠 있는 프로그램 창을 모두 닫고(X 누른 것과 같음 — 저장 여부를 묻는 창은 남을 수 있음)
  3. 작업 관리자의 **AtMessenger** 프로세스를 강제로 끝내고(실행 파일 이름이 `AtMessenger` 로 시작하는 것)
  4. 검은 화면을 없앱니다.
  잠금을 먼저 하므로 창이 닫히는 모습이 검은 화면 위로 비치지 않습니다(잠금 화면 뒤에서 처리).
  결과 페이지의 마지막 갱신 자리에 **⚠ 입력 비상종료 + 시각**이 표시됩니다(다음에 화면을 다시 가리면 지워짐).
  Apphelper 자체와 매크로는 계속 돌아갑니다.
- 한계: Ctrl+Alt+Del 은 Windows 가 막지 못하게 해 둔 키라 막을 수 없습니다(작업 관리자로 Apphelper 를 끄면
  가림도 풀리고 매크로도 멈춤). 남이 실수로 만지는 것을 막는 용도입니다.
- 구조: 입력 차단은 응답이 늦으면 Windows 가 풀어 버리므로, 같은 exe 를 `--cover` 로 별도 프로세스로 띄워
  맡깁니다. 비밀번호는 넘기지 않고 검증값만 넘깁니다.

## 자동 로그인 (테스트용)

편집 화면 → **자동 로그인** 탭. 버튼을 누를 때만 실행합니다(**전체 자동 로그인** = 체크한 항목 차례로, **이 항목 로그인**).

- 항목마다: 이미 **열린 창**(실행 파일 이름 + 창 제목 포함 글자)을 찾아 로그인하고, 없으면 **실행 경로**
  (웹은 주소를 브라우저 경로 또는 기본 브라우저)로 **열어서** 창이 뜰 때까지 기다렸다가 로그인합니다.
- **창 지정**: 로그인 화면을 한 번 클릭하면 실행 파일 이름(웹은 창 제목까지)을 채웁니다.
- **아이디 칸 / 비밀번호 칸 좌표**: 창 왼쪽 위 기준이라 창이 옮겨져도 됩니다. 아이디 칸을 안 정하면 지금 커서가
  있는 칸에, 비밀번호 칸을 안 정하면 아이디 뒤 Tab 으로 넘어가 입력합니다. 마지막에 Enter(선택).
- 글자는 한/영 상태와 상관없이 그대로 입력됩니다. 비밀번호는 Windows 계정으로만 풀리게 암호화(DPAPI)해서
  `data\config.json` 에 저장되고, 결과 페이지에는 올라가지 않습니다.
- 관리자 권한으로 실행되는 프로그램(일부 보안 에이전트)은 Windows 가 일반 프로그램의 입력을 막습니다. 그럴 때는
  Apphelper 를 관리자 권한으로 실행해야 합니다.

## 매크로 켜기/끄기와 원격 조정

- 편집 화면 아래 **매크로 ON/OFF** 버튼(트레이의 실행/일시정지와 같음).
- 설정 → **결과 페이지에서 매크로 조정 허용**을 켜면, 결과 페이지 **매크로** 탭에서 켜기/끄기, 프로필 바꾸기,
  시간대별 작동·분 범위를 바꿀 수 있습니다. PC 가 5초마다 확인해 적용하고, 적용되면 페이지에 "반영됐습니다"가
  뜹니다. 페이지에서 여러 번 눌러도 명령이 쌓여 차례로 적용되며, 10분 넘게 지난 명령은 무시합니다.

## 결과 페이지 (GitHub Pages)

**모든 내용이 GitHub 토큰으로 암호화**되어 있어, 페이지에 PC 앱과 같은 토큰을 넣어야 볼 수 있습니다.
토큰이 없으면 페이지에도, 공개 파일에도 아무 내용이 보이지 않습니다. 토큰을 넣으면 프로그램처럼
**메신저 상태 / 매크로 / PC 전원 / PC 화면** 탭으로 나뉘어 보이고, 마지막에 본 탭을 기억합니다.

- PC 전원 탭의 켜짐/꺼짐은 PC 가 1분마다 올리는 상태로 판단합니다. PC 와 휴대폰 시계가 달라도, 페이지를
  보는 동안 상태가 새로 올라오면 켜짐으로 봅니다.
- 페이지와 앱은 파일을 GitHub contents API(CDN 에 최대 1분가량 캐시됨) 대신 브랜치 최신 커밋에서 직접
  읽어, 방금 올라온 내용(PC 상태·요청·스크린샷)을 바로 봅니다. 커밋이 그대로면 다시 받지 않습니다.
- 공개 `results.json` 에는 `{"enc": 1, "repo": ...}` 만 있고, 결과 전체는 `data.bin` (AES-256-GCM,
  키 = PBKDF2-SHA256(토큰)) 에 있습니다. PC 상태(`status.bin`), 페이지 요청(`request.bin`),
  화면(`screen.bin`)도 같은 키로 암호화됩니다. 페이지가 브라우저 안에서 풀고, 요청도 브라우저에서 암호화합니다.


1. 결과용 레포를 만듭니다 (비공개 레포는 GitHub 요금제에 따라 Pages 사용이 제한될 수 있음).
2. Fine-grained 토큰을 만들고 그 레포 하나에만 **Contents: Read and write** 권한을 줍니다.
3. 편집 화면 → **설정** 에 소유자, 레포 이름, 토큰을 입력하고 "결과 페이지 지금 갱신"을 누릅니다.
   처음 갱신하면 `gh-pages` 브랜치가 생깁니다.
4. 레포 Settings → Pages 에서 Source 를 **Deploy from a branch**, 브랜치를 `gh-pages` / `(root)` 로 지정합니다.

동작 방식:

- 앱은 시작할 때, 매 시간이 시작될 때, 슬롯을 실행한 뒤, 설정을 바꿨을 때 결과를 갱신합니다.
- 갱신할 때마다 `index.html`(이 레포의 `pages/index.html` 템플릿), `results.json`, `.nojekyll` 로
  **부모 없는 커밋(parents=[])** 을 새로 만들고 `gh-pages` ref 를 `force=true` 로 교체합니다.
  브랜치에는 항상 커밋 1개만 남고, main 과 이력이 섞이지 않습니다.
- 커밋 메시지·작성자는 고정값 `update` 입니다.
- 결과 데이터(`data.bin`, 암호화)는 날짜·시간·분·결과와 갱신 시각, 시간대별 설정 분 범위, 메신저 상태만 담고, 7일이 지난 날짜는 갱신할 때 지웁니다.

```json
{"updated": "2026-10-11 14:23",
 "days": {"2026-10-11": {
  "9":  {"r": "실패", "w": [10, 40]},
  "14": {"r": "작동", "m": 23, "k": ["변함!"], "w": [10, 40]},
  "15": {"r": "대기", "w": [0, 59]}
}}}
```

페이지 맨 위에 **마지막 갱신 시각**(몇 분 전인지)이 나오고, 70분 넘게 갱신이 없으면 빨간 경고가
뜹니다 (앱이 꺼져 있거나 PC 가 절전 중). 각 시간대 아래에는 그 시간의 **설정 분 범위**
(예: `설정 10~40분`)가 나옵니다. 이미 실행된 시간은 실행 당시 범위, 대기 중인 시간은 현재 설정입니다.
페이지는 열어 둔 채로 1분마다 새로 불러옵니다.

페이지 표시: `14시 — 23분 작동 [변함!]`, 체크했지만 실행 전이면 `대기`, 실패 또는
지나간 시간인데 실행되지 않았으면 `실패`. 기본은 오늘이고 최근 7일까지 고를 수 있습니다.

### 결과 페이지에서 PC 화면 보기

1. PC 앱: 편집 화면 → 설정 → **결과 페이지에서 스크린샷 요청 허용** 을 켭니다 (기본은 꺼짐).
2. 결과 페이지 아래 **PC 화면** 에 PC 앱에 넣은 것과 **같은 GitHub 토큰**을 한 번 넣습니다
   (그 브라우저에만 저장. **토큰 변경** 으로 지울 수 있음).
3. **지금 화면 보기** → PC 가 30초마다 요청을 확인하므로 보통 1분 안에 화면이 나타납니다.

동작 방식과 보안:
- 페이지는 GitHub API 로 `apphelper-remote` 브랜치의 `request.json` 을 덮어씁니다 (부모 없는 커밋 + force,
  이력 없음). 이 브랜치는 빌드 대상에서 빠져 있습니다.
- PC 앱은 10분이 지난 요청은 무시하고, 같은 요청은 한 번만 처리합니다.
- 화면 이미지(JPEG, 가로 1600px 이하)는 **AES-256-GCM 으로 암호화**해
  `screen.bin` 으로 올립니다. 키는 GitHub 토큰에서 만들어지므로(PBKDF2) 토큰을 가진 사람만 볼 수 있고,
  페이지가 브라우저 안에서 풉니다. PC 에는 최신 1장만 메모리에 두고 파일로 남기지 않습니다.
- PC 앱의 토큰을 바꾸면 이전 화면은 더 이상 올리지 않습니다.

## 기록 최소화

- 포터블: 설치 프로그램 없이 exe 옆 `data/` 에 설정·동작·토큰·메신저 기록을 모두 저장합니다. 레지스트리는 "윈도우 시작 시 자동 실행"을 켰을 때만 값 하나를 씁니다.
- 토큰은 이 파일에만 저장되고, 코드나 레포에는 들어가지 않습니다 (`data/` 는 `.gitignore` 에 있음).
- 화면 비교용 픽셀 값은 메모리에서만 씁니다. 스크린샷 파일은 "안변함!" 결과와 상세 디버그를 켠 시간대에만 `data\screenshots` 에 저장됩니다.
- 로컬 로그는 기본 OFF. 설정에서 디버그 로그를 켜면 `data/debug.log` 에 남습니다.
- 설정 → **전체 데이터 삭제**: `data/` 폴더(설정, 저장된 동작, 토큰, 디버그 로그)를 한 번에 지웁니다.
- 실행 중에는 트레이에만 상주하고 콘솔 창, 팝업, 알림을 띄우지 않습니다.

## 개발

```bash
pip install -r requirements-dev.txt
python -m pytest -q          # 단위 테스트 (Windows 전용 테스트는 다른 OS 에서 건너뜀)
python run_apphelper.py      # 소스로 실행 (Windows 가 아니면 실제로 클릭하지 않는 더미 백엔드)
```

### exe 빌드 (Windows)

```bat
build.bat
```

`dist\Apphelper.exe` 가 만들어집니다. GitHub Actions(`.github/workflows/build.yml`)도 push 할 때마다
Windows 에서 테스트 후 exe 를 빌드해 아티팩트로 올립니다.

## 구조

```
apphelper/
  core/crash.py      crash, N×N 평균 색상, 변화 판정, 핵심 crash
  core/scheduler.py  랜덤 실행 시각 선택, 시간대 슬롯 스케줄러
  core/model.py      데이터 모델, 앱 폴더 JSON 저장/전체 삭제
  core/runner.py     슬롯 블록 순서 실행
  core/results.py    결과 JSON (대기/작동/실패, 7일 보관)
  core/publisher.py  gh-pages orphan 커밋 덮어쓰기 (GitHub Git Data API)
  platform_win.py    Win32 마우스/화면 읽기 (ctypes)
  service.py         스케줄러·실행·결과·갱신 연결
  ui/                편집 화면(드래그 앤 드롭), 대화상자, 좌표 따기
  app.py             트레이 상주, 단일 인스턴스
pages/index.html     결과 페이지 템플릿
```
